# Светофор — риски закупочной документации для поставщика

## ▶ Видео-презентация (4:48)

**[Смотреть ролик](https://github.com/Aludra568/TrafficLight/raw/main/media/svetofor-video.mp4)** — команда, как устроено решение и демонстрация работы (MP4, 19 МБ, со звуком; файл в репозитории — `media/svetofor-video.mp4`).

Кейс-чемпионат B2B-РТС «AI Procurement Copilot», задача 1 «Светофор рисков документов».

Поставщик загружает документы закупки — файлами, архивом или просто реестровым номером из ЕИС — и
получает:

- **светофор**: критично, внимание, без рисков; серый «не оценено», если проверить не удалось;
- **замечания с дословной цитатой и местом в документе** (документ, пункт, страница). Каждая
  цитата сверяется с текстом программой — в отчёт попадает текст документа, а не пересказ модели;
- **карточку закупки**: НМЦК, сроки поставки и оплаты, обеспечение, аванс — у каждого значения
  ссылка на источник;
- **отчёт в Word и PDF** и **черновик запроса на разъяснение**;
- **сравнение редакций** документации.

Правила проверки — данные (YAML), их меняет методолог в интерфейсе без программиста. Закон
закупки (44-ФЗ, 223-ФЗ) определяется по тексту документов; если он не определён, проверяются
правила обоих законов.

## Быстрый старт

Нужен Docker Desktop (или Docker Engine с Compose v2) и около 15 ГБ места.

```bash
git clone https://github.com/Aludra568/TrafficLight.git svetofor
cd svetofor
cp .env.example .env          # необязательно: без файла и без ключа работает демо-режим
docker compose up --build
```

Откройте http://localhost:8080 и войдите:

| Роль | Почта | Пароль |
|---|---|---|
| Специалист по закупкам | specialist@demo.ru | demo |
| Методолог (редактор правил) | methodologist@demo.ru | demo |
| Администратор | admin@demo.ru | demo |

Работать могут несколько человек одновременно: специалист видит только свои проверки, методолог
и администратор — все.

Первый запуск — 5–15 минут: собираются образы и скачивается модель эмбеддингов (около 0,5 ГБ).
Пока она скачивается, поиск по документам идёт по словам, и отчёт об этом пишет.

**Без ключа модели** нажмите «Попробовать на примере»: демо-пакет проверяется по записанным
ответам модели (`samples/demo_llm_cassette.jsonl`). Свои документы без ключа проверяются
правилами по числам и формулировкам, а смысловые правила честно помечаются «не проверено».

## Модель

Результаты получены на **DeepSeek V4.1 Flash** (`deepseek-v4.1-flash`; одна модель — основная и
быстрая, `LLM_SUPPORTS_JSON_SCHEMA=false`). На ней сделаны замеры качества и записана
демо-кассета; на другой модели цифры будут другими.

Подходит любой OpenAI-совместимый провайдер — облачный или свой (vLLM, Ollama). В `.env`:

```dotenv
LLM_BASE_URL=https://адрес-провайдера/v1
LLM_API_KEY=ключ
LLM_MODEL_MAIN=deepseek-v4.1-flash
LLM_MODEL_FAST=deepseek-v4.1-flash
LLM_SUPPORTS_JSON_SCHEMA=false   # true, если провайдер поддерживает response_format=json_schema
```

Затем `docker compose up -d`. Полностью без облака: `docker compose --profile local-llm up --build`
и `LLM_BASE_URL=http://ollama:11434/v1` — документы не покидают контур.

**Других ключей не нужно.** Модель эмбеддингов (intfloat/multilingual-e5-small) работает в контейнере, внешних
сервисов вроде ЕГРЮЛ нет. Загрузка по номеру обращается только к открытому сайту zakupki.gov.ru.

## Качество — измерено

**Синтетика** (`eval/synthetic`, 17 пакетов с размеченными рисками, DeepSeek V4.1 Flash,
21.10.2026; в скобках — 95 % доверительный интервал, бутстрэп по пакетам):

| Подход | Полнота | Точность |
|---|---|---|
| Светофор | **1,00** (1,00–1,00) | **1,00** (1,00–1,00) |
| «Весь текст и список рисков в одном запросе к той же модели» | 0,79 | 0,81 |

Полнота — доля заложенных рисков, которые найдены; точность — доля верных замечаний. Синтетику
написала команда, поэтому на ней 1,00 — это проверка механизма, а не реальности.

**Настоящие закупки из ЕИС** (`eval/real`, 6 пакетов на 25–197 страниц: товары, работы, услуги,
пять регионов): **полнота 0,87**, **точность 0,94**, сбоев 0 (замер 31.10.2026, после улучшения поиска
фрагментов и разбора сроков, заданных датой). Правила уточнялись по ошибкам на этих же пакетах, поэтому на
новых закупках точность может быть ниже. Эталон размечен по критериям правил (риск — только то, что выходит за обычные
условия 44-ФЗ), а не юристом; разметку делал Claude, видевший отчёт системы до разметки, —
возможна предвзятость. Пропуски — в основном неочевидные случаи «зависит от третьих лиц»; лишние —
осторожное «срок не найден числом — проверьте вручную», когда срок задан датой. Документы
скачаны с zakupki.gov.ru 21.10.2026; ФИО должностных лиц и контакты обезличены.

OCR сканов — 99,78 % символов верно (`make eval-ocr`).

Повторить: `make eval SET=synthetic`, `make eval SET=real`, `make eval-baseline SET=synthetic`;
отчёты — `eval/results/`.

## Критерии приёмки задачи 1

| № | Критерий | Как выполнено |
|---|---|---|
| 1 | Файл 50+ страниц без 504 | загрузка и обработка разделены очередью: PDF на 60 страниц — ответ на загрузку 1,1 с, обработка 93 с (`make acceptance`) |
| 2 | Новое правило без кода | правила — YAML и редактор в интерфейсе, проверка правила на тексте до сохранения |
| 3 | UX для не-технических | русский интерфейс без жаргона, светофор с иконкой и словом, клик по замечанию — место в документе подсвечено |
| 4 | OCR ≥ 95 % | OCRmyPDF + Tesseract rus+eng: 99,78 % по символам, минимум по странице 99,5 % |
| 5 | 20 страниц < 2 минут | свежий пакет из ЕИС, 4 файла, 25 страниц — 85 с с моделью |
| 6 | Ссылка на раздел | у замечания — документ, пункт и страница; у противоречия — оба места; у «условие не найдено» — где искали |
| 7 | `docker compose up --build` | проверено на чистой машине без `.env`; демо и критерии — `make smoke`, `make acceptance` и CI |

## Как это устроено

```
браузер (React) ──> nginx ──> API (FastAPI) ──> PostgreSQL + pgvector
                                   │
                                   └──> Redis ──> воркер документов: распаковка, LibreOffice → PDF,
                                                   OCR, разделы и пункты, эмбеддинги, загрузка из ЕИС
                                            └──> воркер анализа: карточка закупки, правила, сверка цитат
```

Семь контейнеров, запуск одной командой. Тяжёлая работа — только в задачах Celery: загрузка
сразу возвращает ответ, ход проверки виден по этапам.

**Как проверяется пакет:** распаковка (ZIP, RAR, 7z, вложенные архивы) → конвертация Word, Excel,
RTF, XML из ЕИС в PDF → OCR сканов → разбор на разделы и пункты → карточка закупки (грамматики и модель
сверяют друг друга) → 39 правил → сверка каждой цитаты с текстом → светофор.

**Главный принцип: цвет ставит правило, а не модель.** Правила (`rules/44fz_supplier_base.yaml`,
39 штук со ссылкой на норму, из них 18 — для 223-ФЗ): пороги по значениям карточки, поиск
формулировок, сверка документов между собой и значений внутри документа, смысловая проверка
моделью. Модель
отвечает только «нарушение / в порядке / не найдено» с цитатой; цитату, которой нет в документе,
программа отбрасывает.

**Зелёный нужно заслужить.** «Рисков нет» — утверждение, которое требует доказательств: всё
прочитано, правила уровня «критично» проверены, у «в порядке» есть основание. Иначе — серый «не
оценено» с причиной. Текст документа — данные: скрытый текст и «указания для ИИ» внутри файла
обнаруживаются и не меняют вердикт.

| Модуль | За что отвечает |
|---|---|
| `backend/svetofor/pipeline` | документы: распаковка, конвертация, OCR, структура, загрузка из ЕИС |
| `backend/svetofor/rules` | движок правил, карточка закупки, сверка цитат (`verify.py`) |
| `backend/svetofor/llm` | единый шлюз к модели: схема ответа, кэш, лимиты, промпты |
| `backend/svetofor/reports` | отчёт, Word и PDF, сравнение редакций, запрос разъяснений |
| `backend/svetofor/api`, `tasks` | HTTP API, вход и роли, задачи Celery |
| `frontend` | интерфейс: отчёт, документ с подсветкой цитаты, редактор правил |
| `rules`, `samples`, `eval` | правила, демо-пакеты, наборы для оценки качества |

Стек: Python 3.12, FastAPI, SQLAlchemy 2, Celery + Redis, PostgreSQL 16 + pgvector, LibreOffice,
OCRmyPDF + Tesseract, PyMuPDF, TEI (multilingual-e5-small), React 18 + TypeScript, Ant Design 5, nginx, Docker
Compose.

## Загрузка из ЕИС по номеру

Реестровый номер — 19 цифр (44-ФЗ) или 11 цифр (223-ФЗ). Сервис скачивает печатную форму
извещения и все вложения с zakupki.gov.ru, собирает пакет и запускает обычную проверку. Запросы
идут только на zakupki.gov.ru по HTTPS с проверкой сертификата (корень Минцифры лежит в
репозитории, `backend/svetofor/pipeline/certs`), из страниц берутся только идентификаторы файлов.
Если ЕИС недоступна, сервис просит загрузить документы архивом. Выключается `EIS_FETCH=false`.

## Безопасность

- Пароли — Argon2, вход по токену с ограниченным сроком, лимит попыток входа.
- Специалист видит и меняет только свои пакеты; правила меняет только методолог.
- Лимит одновременных проверок на пользователя — защита от расхода платной модели.
- Загрузка: лимиты размера, числа файлов, вложенности и степени сжатия архивов (zip-бомбы),
  защита от путей вида `../`; макросы LibreOffice выключены, внешние ссылки из документов не
  загружаются.
- nginx: CSP и заголовки безопасности, лимит частоты запросов; база и Redis — во внутренней сети
  Docker без выхода наружу; процессы приложения без привилегий.
- Ключи — только из окружения; тексты документов и ключи не пишутся в журнал.

Перед установкой с доступом из сети: `DEMO_USERS=false`, свои `JWT_SECRET` и `POSTGRES_PASSWORD`,
HTTPS на внешнем прокси, `API_DOCS=false`.

## Настройки

Все переменные с пояснениями — в `.env.example`. Главные:

| Переменная | Что задаёт |
|---|---|
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL_MAIN`, `LLM_MODEL_FAST` | модель |
| `DEMO_USERS`, `DEMO_USERS_PASSWORD` | демо-учётки |
| `MAX_UPLOAD_MB`, `MAX_FILES`, `MAX_PAGES_PER_DOC` | лимиты пакета |
| `MAX_ACTIVE_CHECKS_PER_USER` | одновременных проверок у пользователя |
| `OCR_JOBS` | параллельность OCR (на машине с 8 ГБ памяти — 2) |
| `EIS_FETCH`, `API_DOCS` | загрузка из ЕИС, описание API без входа |

Смена модели — `EMBED_MODEL`/`EMBED_DIM` и `make reembed`.

## API

Описание — http://localhost:8080/api/docs (Swagger).

```bash
# 1. Вход — токен
TOKEN=$(curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"specialist@demo.ru","password":"demo"}' | jq -r .access_token)

# 2. Загрузить пакет (ZIP, RAR, 7z, PDF, DOCX…; до 100 МБ) — проверка идёт в очереди
CHECK=$(curl -s -X POST http://localhost:8080/api/checks \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@samples/demo_44fz_postavka.zip" | jq -r .check_id)

# или по реестровому номеру из ЕИС → номер задачи; ход — GET /api/checks/eis/{task_id}
curl -s -X POST http://localhost:8080/api/checks/eis -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" -d '{"number":"0362100026126000023"}'

# 3. Статус и светофор (light: red | yellow | green | gray)
curl -s http://localhost:8080/api/checks/$CHECK -H "Authorization: Bearer $TOKEN" | jq '{status, light}'

# 4. Отчёт: замечания с цитатами, разделом и страницей, карточка, исходы всех правил
curl -s http://localhost:8080/api/checks/$CHECK/report -H "Authorization: Bearer $TOKEN" \
  | jq '.findings[] | {rule_code, severity, title, quote, section_path, page_from}'

# 5. Отчёт в Word и черновик запроса на разъяснение
curl -s -X POST "http://localhost:8080/api/checks/$CHECK/export?format=docx" \
  -H "Authorization: Bearer $TOKEN" -o report.docx
curl -s -X POST http://localhost:8080/api/checks/$CHECK/clarification \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{}' -o clarification.docx
```
